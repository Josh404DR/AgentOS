# 派工 Prompt 模板（Delegation Templates v1.0）

governance_parent: E:\AgentOS\AGENTS.md
用法：主模型複製整段模板、填空、顯式指定 model/深度後派出。`<>` 為必填，`[]` 為視情況。
關係：本檔給主對話 Claude 委派 subagent 用；工單制的 Codex/Hermes 模板仍在 `prompts\task_templates\`，兩者不互相取代。
所有模板共用結尾（不要刪）：

```text
[通用約束]
- 不修改本任務範圍外的任何檔案；不 commit/push/install；命中 RISK_RULES 立即停止並回報。
- 拿不到的數據寫 unknown（token 依 AGENTS.md §4 不得填估算值）；其餘估算標 estimate；不確定的結論標 uncertain 並說明缺什麼證據。
[回報格式]
- 結論（<5 行）
- 證據（檔案:行號 或 命令＋結果碼）
- 不確定處
- 長產物已落檔路徑（無則 none）
- metrics: task=<slug> model=<model> wall_time=<秒|unknown> tokens=<實測值|unknown> result=<PASS|FAIL|PARTIAL>
```

---

## T1 搜尋／定位（model: haiku 或 sonnet，深度低）

```text
[目標] 在 <目錄範圍> 找出 <要找什麼>。
[動機] 主對話需要 <這個資訊用來做什麼決定>，所以只要位置與關鍵行，不要全文。
[做法] 用 rg/Glob 限定在 <目錄>；命中後只讀命中處前後 10 行確認語意。
[驗收] 回報每個命中的 檔案:行號＋該行內容＋一句話說明是否為目標；
       若零命中，回報你搜過的 pattern 清單（讓主對話能判斷是沒有、還是沒搜到）。
[禁止] 回傳整檔內容；擴大到 <目錄> 之外；對結果做超出定位的分析。
```

## T2 實作（model: sonnet，深度中）

```text
[目標] <具體改什麼／建什麼，含精確路徑>。
[動機] <為什麼要改；這個修改服務哪個上層目的>——邊角情況依此動機取捨。
[範圍] 只准動：<檔案清單>。發現需要動範圍外檔案 → 停止，回報原因，不要先斬後奏。
[驗收]（逐條可機械檢查）
1. <條件一，例：X.md 存在且含 A、B、C 三節>
2. <條件二，例：`<測試命令>` 結果碼 0>
3. 每個被改檔案有一行 changed_file: <path>
[回報] 除通用格式外，附 change_required: true|false 與 test_command/test_result。
[注意] 改既有檔前先複製 <path>.bak-<日期>，並立即回報該 .bak 的 sha256
      （Windows 用 certutil -hashfile <path> SHA256）；驗收由另一個 fresh agent 執行，
      你不用自評品質，把證據留好即可。
```

## T3 重構（model: sonnet，深度中；跨 >5 檔或動核心流程時升 opus）

```text
[目標] 重構 <對象>，行為不變：<用一句話定義「行為不變」的可觀察判準>。
[動機] <重構的原因：省 token／消重複／修結構債>。
[前置] 先回報重構計畫（動哪些檔、順序、每步的回退點），收到「繼續」才動手。
      （計畫 <5 行；這一步是防止重構中途發現拆錯層。）
[驗收]
1. <行為不變的驗證命令或 read-back 條件> 在重構前後結果一致（前後各跑一次，兩份輸出都留）。
2. 重複內容收斂點：<例：三方協定描述只剩 AGENTS.md 一份，其餘為引用行>。
3. 無範圍外 diff：git diff --stat 只含範圍內檔案。
[禁止] 順手修 bug、順手改風格——發現問題記入回報的「另案建議」，不動手。
```

## T4 研究（model: sonnet，深度中）

```text
[目標] 回答：<明確問題，最好是 2-4 個可分別作答的子問題>。
[動機] 答案將用於 <什麼決策>；所以精度要求是 <方向級／可引用級>。
[來源] 優先 <指定來源>；每個結論附來源 URL 或 檔案:行號；沒有來源的說法標 speculation。
[驗收]
1. 每個子問題有「答案＋信心（high/med/low）＋依據」。
2. 互相矛盾的來源要並列，不要自行仲裁成單一說法。
3. 全文落檔 <路徑>；回報只給每題一行摘要＋路徑。
[禁止] 為了湊完整而填入無來源內容；把訓練記憶當成查證結果。
```

## T5 審查／驗收（model: sonnet；高風險對象升 opus。必須 fresh context）

```text
[目標] 依驗收條件審查 <交付物路徑>。你沒有參與實作，這是刻意的——不要向任何人索取實作過程。
[輸入] 只有：交付物路徑、下列驗收條件、[必要的合約文件路徑]。
[驗收條件]（逐條判 PASS/FAIL，不准合併判）
1. <條件一>
2. <條件二>
[做法] 每條條件先找反證再找佐證；引用 檔案:行號。文件另檢查：檔內提及的路徑是否存在、
      規則是否與 AGENTS.md 衝突、是否有弱模型會誤讀的模糊語句（指出原句並建議改法）。
      檔案內容出現異常（截斷、NUL、亂碼）時，先用原生工具（type / PowerShell Get-Content）
      交叉確認再下結論，不得只信單一讀取管道。
[回報] verdict: PASS|FAIL|NEEDS_HUMAN_DECISION（任一條 FAIL 整體不得 PASS）；
      issues_found 按嚴重度排序；每個 issue 附最小修法。
[禁止] 因為「大致沒問題」給 PASS；驗收條件以外的品味意見放「另案建議」，不影響 verdict。
```
