# 需求成形模板（Raw Intake v1.0）

governance_parent: E:\AgentOS\AGENTS.md
用途：管線第一站——把 Josh 的自然語言毛坯磨成三件套（目標與動機／驗收條件／回報格式）工單草稿，停等核准後才進實作。
觸發詞：訊息以「需求成形：」開頭即套用本檔。

## 1. 毛坯格式（Josh 端，缺欄不擋）

```text
需求成形：
想要：<白話說 what>
因為：<白話說 why>
紅線：<不准動什麼；可空>
急度：<今天／本週／有空；可空>
```

缺欄由成形者補問，不得拒收、不得自行腦補填入。

## 2. 成形者（Claude）五步

1. 複述目標：一句話複述你理解的「想要＋因為」。理解錯 Josh 會糾正。
2. 判可逆等級並說明理由：綠＝改錯免費還原；黃＝回得去但燒輪次（先磨規格再派）；
   紅＝刪、外、錢、鑰。紅色不產工單，改產 escalation 提案
   （含精確路徑、原因、證據、相依性檢查、可回復方案，走 ESCALATION_QUEUE）。
3. 問 Josh 最多 3 個會影響方向的問題，隨草稿一併送出，不等回答才出草稿；
   細節自己決定並逐條標「假設：」。
4. 套 docs\claude_ops\30_DELEGATION_TEMPLATES.md 選對應模板（T1-T5）產出完整工單草稿：
   磁碟現狀看不到的部分一律寫「先讀檔核實，行號可能偏移」；
   驗收條件逐條可機械檢查；結尾附 30 號檔通用約束與回報格式標準段。
5. 草稿末附一行「這份工單最可能失敗的地方：<一句話>」。

## 3. 硬規則（違反即 FAIL）

- 成形產物是工單「草稿」，首行必標 `status: awaiting_josh_approval`。
- Josh 明確回覆核准前不得進入實作；「沒反對」不算核准。
- 草稿落檔於對應工單目錄：`data\tasks\<task_id>\TASK.md`；
  task_id 尚未產生時先落 `data\tasks\draft-<YYYYMMDD>-<slug>\TASK.md`，核准後再併入正式工單。
- 拿不到的資訊寫 unknown；估算標 estimate（依 AGENTS.md §4）。
