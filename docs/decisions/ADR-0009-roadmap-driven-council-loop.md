## 內容

目標運作模型（完整迴圈）：

1. **想法接上地圖**：Josh 丟想法 → 綠色 proposed 節點掛上版圖。
2. **議會討論**：針對 proposed 節點與其在 roadmap 上的路線，
   多 agent 議會出意見 → 匯總成「決策路徑」提案。
3. **Josh 審核**：唯一人工關卡在這裡——審的是決策路徑，
   不是之後的每一件事。
4. **團隊自主開工**：agents 直接讀 roadmap，對 accepted 且未實作
   的節點自己開工單執行（TASK.md 帶 related_adr 血緣）。
5. **關單自動落地**：工單 verify PASS ＋關帳 → 對應 ADR 自動標
   landed，證據＝dispatch_id。不再要 Josh 逐案蓋章——他的核准
   已在步驟 3 完成，下游自動化與治理一致。
6. **推薦下一步**：完成後系統依 result 鏈推薦下一個節點與新想法
   （新綠節點）→ 回到步驟 2。

人的角色收斂成兩點：丟想法、審路徑。其餘由地圖＋議會＋pipeline 承擔。

## 想法入圖情境矩陣（2026-07-13 Josh 補充）

議會的第一項職責是「掛圖判定」：想法進來，先判要不要上圖、掛在哪。

| 情境 | 來源 | 判定者 | 結果 |
|---|---|---|---|
| A1 | Hermes 丟想法，與現有路線相關（如流程優化） | 議會 | proposed 綠節點＋自動連線到相關節點，附判定理由供 Josh 審 |
| A2 | Hermes 丟想法，屬戰略但與現有節點無關 | 議會 | 孤島綠節點（上圖、暫無連線），待議會或 Josh 後續接線 |
| A3 | Hermes 丟的是純 op／一次性任務 | 議會（或 router 先篩） | **不掛圖**，走既有 typed dispatch 工單管道 |
| B | Josh 親自在前端畫圖 | Josh 本人 | 必定有關聯——他自己放位置、自己連線，議會不覆核掛圖性，仍可對路線出意見 |
| C | 執行中從 result 鏈長出的優化點（如 1316 確診的四個問題） | 議會 | proposed 節點自動掛到相關 core（學習迴路的輸出端） |
| D | 月度回溯挖掘掃出的無主決策 | 議會 | proposed 節點＋標注「追認候選」待 Josh 審 |

判定規則本身寫成文件（skill 形式）供議會讀取，新情境出現時補列——
矩陣是開放的，不是封閉的。

註：A3 的「想法 vs 任務」初篩與 ADR-0006 router 分類是同一問題的
兩層——router 先分 task_kind，疑似戰略想法才進議會掛圖判定。

### 議會設計討論收斂（2026-07-13，Claude ⇄ Josh 對話草案，尚未定案）

**目的（兩層，Josh 定義）**：
1. 監察制衡——制衡對象包含 Josh 自己，不是只審其他 agent。制衡力
   本質是「反向思考」，用意是防止 Josh 困在自己的框架內迷失方向，
   **不是否決權**；議會不能卡住 Josh，只能強制把反對意見完整攤開
   給他看，他仍是唯一批准關卡（呼應本 ADR 原設計）。
2. 消化與呈現——把系統現況整理成 Josh 能選的 roadmap，前端可視化
   決策圖是這個功能的直接產出，不是附屬品。

**治理位階比喻（Josh 提出）**：議會＝地方治理，Josh＝中央治理，
地方治理最終流向中央；經 Josh 核准後即「規則＝法律」，不是仍可
隨意翻案的建議（但也要留意朝夕令改的穩定性風險）。

**議會輸出契約**：不能只給風險判定（「預算超標／風險過高」屬單純
告知，不夠）。團隊的意義是「提出問題、解決問題」，輸出必須是
**問題＋風險＋解決辦法**的完整套組，由「調度者」統整成單一決策
路徑提案交給 Josh。

**角色草案（Josh 初版，4 席，尚未定案）**：
1. **反向思考者**——給予不同角度、不同邏輯面的回應。
2. **法典者**——遵循 AGENTS.md／ADR 全部治理規則給予回應，檢查
   一致性（可能與本次對話中發現的 current_state.md 優先序衝突、
   ADR 版本 drift 這類問題屬同一職能）。
3. **正向回應者**——從 Josh 的發言延伸補強，把話「圓滿發揮」
   （例：Josh 只說「決策圖」，這個角色會腦補出一堆優化點）。
   **注意**：這個角色的擴張傾向，結構上正好與當初逼出 ADR-0010
   收斂紀律的「功能過多」模式同源，需要法典者／調度者制衡，
   待確認調度者「找最佳回應」的判準是否錨定 ADR-0010 精神。
4. **調度者**——議會最重要的角色，綜合出最佳回應並適時喊停，
   同時可能是 ADR-0009 原回頭條件「議會 token 成本超過決策價值
   → 降級」這個煞車的實際執行者。

**尚未解決、需要 Josh 下一輪定案的缺口**：
- Josh 原始定義議會目的時提過「預算制衡」，但上面 4 席沒有一個
  明講「這件事值不值得花」——是併入某一席（法典者？反向思考者？）
  還是需要獨立第 5 席，未定。
- 新增觸發情境：除了既有 `[議會]` 前綴主動觸發，還有「連 Josh 自己
  都拿不定主意」時的被動／反應式觸發——議會此時要給開放性選項，
  不是單一結論。這條需要補進上方「想法入圖情境矩陣」。
- 議會人數與模型分配：4 席是否每次全員到場，還是依主題彈性（呼應
  token 成本考量），未定。

## 回頭條件

- 自動落地出現「假落地」（verify PASS 但實際沒解決）→ 在關單與
  落地之間加抽查層，而非退回逐案人工蓋章。
- 議會 token 成本超過其決策價值 → 降級為單 agent 意見書＋Josh 直審。
